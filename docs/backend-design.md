# 后端设计文档（概览） ✅

## 简介
本文件为 PlantKnow 项目准备的后端设计指导，不包含具体代码实现，覆盖：需求拆解、架构选择、接口设计、数据与迁移策略、部署/运维、测试和安全等方面，供团队在实现后端时参照。

---

## 目标与约束 🎯
- 提供稳定的 API 给 Android 客户端使用（REST/GraphQL）。
- 可扩展、易维护、安全可靠、易于部署与监控。
- 支持认证/权限、离线/同步策略（若客户端需要）、高并发读场景优化。

---

## 功能需求（高层）
- 用户注册、登录、资料管理与权限控制
- 植物数据的增删改查（种类、属性、标注、图片等）
- 搜索与筛选（名称、特性、上传者等）
- 图片上传与存储（缩略图/原图管理）
- 日志/活动/审计记录
- 管理后台接口（可选）

---

## 非功能需求（NFR）
- 安全：HTTPS、认证、最小权限、密钥管理
- 性能：API 响应 < 300ms（目标）
- 可用性：99.9%（根据预算调整）
- 可扩展性：方便水平扩展，支持缓存策略
- 可维护性：良好文档、测试覆盖与自动化部署

---

## 技术选型建议 🔧
- 平台/语言：
  - Java/Kotlin + Spring Boot（与 Android 生态契合、成熟）、或
  - Node.js + NestJS/Express（快速迭代），或
  - Python + FastAPI（开发效率高）。
- 数据库：PostgreSQL（关系型、地理与全文搜索扩展）；如需更高写吞吐或简单 KV，可辅以 MongoDB 或 DynamoDB。
- 缓存：Redis（热点数据、会话、限流、短期缓存）。
- 文件存储：对象存储（S3 / 阿里 OSS / 腾讯 COS）用于图片与大文件，数据库仅保存元数据/URL。
- 身份认证：JWT 或 OAuth2（使用库/服务如 Keycloak、Auth0 根据需求决定）。
- ORM/迁移：Hibernate + Flyway/Liquibase（Java）；TypeORM/Prisma（Node）；Alembic（Python）。
- 容器与部署：Docker + Kubernetes（生产），小团队可先用 Docker Compose / 云 PaaS（例如：Heroku、Render、Cloud Run）。
- CI/CD：GitHub Actions（自动构建、测试、镜像推送、部署）。
- 监控/日志：Prometheus + Grafana（指标），ELK/EFK 或 Grafana Loki（日志），OpenTelemetry（链路追踪）。

---

## 架构建议 📐
- 单体应用（Monolith）先行：快速迭代、部署简单
- 随需求增长拆分为服务：认证服务、媒体服务（图片处理/存储）、主数据服务（植物数据）、后台管理服务
- 接口层（Controller）→ 服务层（业务逻辑）→ 仓储层（DB/外部）
- 使用反向代理/网关（NGINX 或 API Gateway）做 TLS、限流、统一鉴权、版本路由

---

## API 设计要点 / 接口规范 🧭
- 风格：RESTful（或 GraphQL，当需求需要灵活查询时）
- 版本控制：/api/v1/
- 统一错误响应：{ code, message, details(optional) }
- 分页：limit/offset 或 cursor-based
- 资源建模：清晰划分资源与关系（用户、plant、image、tag）
- 文件上传：采用分片/预签名 URL（减轻后端负担）
- 安全：对敏感接口强制 HTTPS 与鉴权

---

## 数据建模与迁移 📦
- 设计规范：尽量规范化（第三范式），对查询热点做适度反规范化以优化性能
- 索引策略：针对常用过滤/排序字段建索引；谨慎添加，避免写放大
- 迁移工具：使用 Flyway/Prisma Migrate 等，所有迁移应进入版本控制
- 备份：定时备份数据库与对象存储，制定恢复演练计划

---

## 鉴权与授权 🔐
- 认证：JWT（短期 access token + 可选 refresh token）或 OAuth2
- 授权：基于角色的 RBAC 或基于属性的 ABAC，按需精细化
- Token 管理与撤销：短过期 + 黑名单或 token 版本号方案

---

## 安全加固建议 ⚠️
- 强制 HTTPS，防止中间人攻击
- 输入校验与输出转义，避免 SQL 注入、XSS 等
- 敏感数据加密（静态与传输中）
- 使用 Secrets 管理（Vault / 云 KMS）
- 实施速率限制、IP 黑名单、WAF（按需）

---

## 性能与扩展性 📈
- 缓存层（Redis）：热点查询缓存、短期数据缓存
- 静态/媒体使用 CDN 与对象存储
- 异步处理：将长耗时任务（如图片处理）放入消息队列（RabbitMQ、Kafka、SQS）由后台 worker 处理
- 数据分片与读写分离（数据库水平扩展时考虑）

---

## 可观测性：日志、监控与追踪 🔍
- 结构化日志（JSON），集中化采集
- 指标：请求率/错误率/延迟/业务 KPI（使用 Prometheus）
- 链路追踪：OpenTelemetry / Jaeger
- 告警：基于 SLO / 错误率 & 关键阈值配置告警

---

## 部署、CI/CD 与运维 🚀
- CI：代码检查、单元测试、集成测试、构建镜像
- CD：自动推送到 staging，手动/自动到 production（根据策略）
- 配置管理：环境变量 + 配置中心
- 基础设施即代码：Terraform / CloudFormation（建议）
- 回滚策略与黑烟测试：有能力快速回滚与快速验证线上健康

---

## 测试策略 ✅
- 单元测试：服务层与工具方法
- 集成测试：数据库、存储的真实交互（在 CI 的隔离环境）
- E2E 测试：关键业务流程（用户登录、上传图片、查询）
- 合约测试：前后端 API contract（Pact 等）

---

## 隐患与注意事项 💡
- 图片/大文件处理要注意成本（流量/存储）与性能
- 身份系统尽量使用成熟方案（避免自行实现全部 OAuth2 功能）
- 设计起初应考虑数据迁移与版本演进（向后兼容）

## 实施里程碑（建议）📅
1. 确定技术栈与云/托管服务（1-2 天）
2. 设计基础数据模型与 API（2-3 天）
3. 搭建开发环境与 CI（2-4 天）
4. 实现认证与基本用户流（2-4 天）
5. 实现植物资源基本 CRUD（3-6 天）
6. 图片上传/处理与对象存储集成（2-5 天）
7. 自动化测试与性能测试（持续）
8. 部署到 staging 与验证（1-2 天）
9. 上线与监控告警配置（1-2 天）
